# Docker deployment on a VPS

The whole site runs from `docker-compose.yml` with no external database:

| Service   | What it does |
|-----------|--------------|
| `db`      | PostgreSQL 18. Data persists in the `pgdata` volume. It is reachable only on the internal Docker network, not from the internet. |
| `migrate` | One-shot job: `prisma migrate deploy` once `db` is healthy. `web` waits for it to succeed. |
| `web`     | The Next.js standalone server (non-root, port 3000, health-checked via `/robots.txt`). ISR and optimized images persist in the `next_cache` volume. |
| `caddy`   | Public reverse proxy on ports 80/443. It issues and renews Let's Encrypt certificates, redirects HTTP to HTTPS, adds HSTS and compression, and 301-redirects `www.` to the apex domain. |

The app's `DATABASE_URL`/`DIRECT_URL` are generated by Compose from `POSTGRES_*`; any database URL in the env file is ignored. Image uploads go to Cloudinary when its keys are set. Without those keys, uploads are stored inline in the database, which makes pages much heavier, so configure Cloudinary in production.

## 1. Prepare the server (once)

1. Point DNS `A` (and `AAAA` if you have IPv6) records for `matiitechnologies.com` **and** `www.matiitechnologies.com` at the VPS.
2. Install Docker Engine with the Compose plugin: `curl -fsSL https://get.docker.com | sh`.
3. Open only ports 22, 80 and 443, e.g. `ufw allow OpenSSH && ufw allow 80,443/tcp && ufw allow 443/udp && ufw enable`.

## 2. Configure

```bash
git clone <repo-url> matii && cd matii
cp .env.production.example .env.production
nano .env.production   # DOMAIN, POSTGRES_PASSWORD (openssl rand -hex 24), ADMIN_PASSWORD, keys
```

`NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME` and `SEO_INDEXING_ENABLED` are compiled into the image. If you change them, rebuild. Set `SEO_INDEXING_ENABLED=true` only on the real production server; a staging VPS must use `false` so it stays `noindex`.

Do not change `POSTGRES_PASSWORD` after the first start: Postgres sets it only when it creates the `pgdata` volume.

## 3. Start / update

```bash
docker compose --env-file .env.production up -d --build --wait
```

Run the same command after `git pull` to deploy a new version. Migrations run first; if they fail, the old `web` container keeps serving.

This builds on the VPS itself. For automatic deploys of prebuilt images on every push to `main`, which needs no git checkout or build on the server, use [CI/CD](CI-CD.md) instead.

## 4. Import existing content (once)

A new `db` starts empty. To copy the current Neon content into it (this replaces the Docker database's contents and only reads from Neon):

```bash
SOURCE_DATABASE_URL='postgresql://USER:PASSWORD@ep-XXXX.REGION.aws.neon.tech/neondb?sslmode=require' \
  sh scripts/docker-import-database.sh
```

Use the direct (non `-pooler`) URL. The script prints the imported counts, clears the app's data cache and restarts `web`.

## 5. Backups

```bash
# Back up
docker compose --env-file .env.production exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > backup-$(date +%F).dump
# Restore
docker compose --env-file .env.production exec -T db sh -c 'pg_restore --clean --if-exists --no-owner -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < backup-YYYY-MM-DD.dump
```

Schedule the backup command with cron and copy the files off the server. `docker compose down -v` deletes the `pgdata` volume and with it the database, so use plain `docker compose down`.

## Useful commands

```bash
docker compose --env-file .env.production ps -a           # status and health
docker compose --env-file .env.production logs -f web     # app logs
docker compose --env-file .env.production logs migrate    # migration output
curl -I http://127.0.0.1:3000/                            # bypass Caddy on the VPS
docker image prune -f                                     # reclaim space after updates
```

## Trying the stack locally

Set `DOMAIN="localhost"` in `.env.production` and start it as above. Caddy serves `https://localhost` with its own local certificate, so browsers show a warning. Pass `-k` to curl.

## Verify SEO after the first production deploy

```bash
curl -sI https://www.matiitechnologies.com/ | grep -i location   # 301 → apex
curl -s https://matiitechnologies.com/robots.txt                 # Allow + Sitemap line
curl -s https://matiitechnologies.com/sitemap.xml | head
node scripts/verify-seo.mjs https://matiitechnologies.com        # full check (from a dev machine)
```

Then submit `https://matiitechnologies.com/sitemap.xml` in Google Search Console and Bing Webmaster Tools.
